## 画面に載った友人は、交友関係の全員とは限らない

**アプリの分類別人数が示すのは、まず登録された範囲です**。[参考動画](https://youtu.be/m94kZNtm3Q8)では、生年月日を登録してタイプを確認し、QRコードで友人を追加して、五行別の表示や相性を見る操作が紹介されています。五行をそろえることがよい調和になる、登録状況から自分が好むタイプが分かるという説明は、**動画内の見解**です。

この記事は動画時点の操作説明を材料にしています。現在のアプリの機能や表示を検証した利用ガイドではありません。考えるのは、友人の一覧を見て「私はこのタイプばかり選ぶ」と判断する前に、何人がどの条件で登録されたかを確かめる方法です。

## 数字の評価

分類は(a)暦の計算で確かめられる事実、(b)統計等で確認できる事実、(c)動画の解釈・経験則で根拠未提示のものです。画面操作の件数は、心理傾向の統計とは分けます。

| 動画に出る数字・数量       | 分類と計算・確認方法                        | 確からしさ                                                      |
| -------------------------- | ------------------------------------------- | --------------------------------------------------------------- |
| 入力例の1966年6月6日       | (a) 暦上の日付として扱える                  | 個人の出生事実や表示された命式の正確さはこの記事では検証しない  |
| 10タイプ                   | (c) アプリの人物分類として紹介              | 分類が10あることから人物理解の精度は算出できない                |
| 木火土金水の5分類          | (c) 友人をまとめる区分                      | 5区分の人数が均等なら関係が良好になるという統計はない           |
| 友人追加で「1」が付く説明  | (b)で確認する操作上の件数、心理効果は未確認 | 動画の操作説明として扱い、現在の仕様や重複除去を保証しない      |
| 2人の相性                  | (c) 関係についての解釈                      | 2人の組という範囲と、相性の実証は別                             |
| 毎日変わる助言、最初の画面 | (c) 更新頻度と操作順の説明                  | 1日ごとの更新は助言の的中率ではなく、操作順は効果の順位ではない |

この動画から、(b)として確認済みの友人分布や、五行をそろえた場合の改善率は得られません。また、出生時刻が分かる場合の入力にも触れていますが、字幕だけから計算規則を補完しません。入力した日付と人物像の解釈を分ける点は、[出生データを先に確認する記事](/blog/birth-data-before-interpretation)で扱っています。

## 登録率が違えば、画面上の割合も変わる

以下は記事独自の架空例です。本人が交友関係の対象として挙げた20人について、説明のため各分類が4人ずつだったと仮定します。この設定は実際の友人や一般の人口分布ではありません。

| 分類 | 対象の友人 | 登録された人数 | 登録率 |
| ---- | ---------- | -------------- | ------ |
| 木   | 4人        | 4人            | 100%   |
| 火   | 4人        | 2人            | 50%    |
| 土   | 4人        | 2人            | 50%    |
| 金   | 4人        | 1人            | 25%    |
| 水   | 4人        | 1人            | 25%    |
| 合計 | 20人       | 10人           | 50%    |

画面の中では木の割合が4÷10＝40%です。一方、最初に挙げた20人の中では4÷20＝20%です。割合が違う理由は、この例では分類ごとの登録率が違うからです。木の人を他の分類の2倍好むという結論は導けません。

現実には、未登録の人の分類自体が不明な場合もあります。そのときは表の対象人数を推測で埋めず、「登録10人のうち4人」と範囲を限定して書けます。未登録の相手の生年月日を集めなければ、この画面を見てはいけないという意味でもありません。分からない範囲を残したまま読むことができます。

## 追加の回数、アカウント数、人数をそろえる

QRコードを読み取った回数と、実際の友人の人数も同じとは限りません。例えば、ある記録に12件の追加操作があり、そのうち同じ相手への再操作が2件含まれていたら、残る相手は10人です。この算術は12−2＝10ですが、紹介されたアプリがそのように処理するという説明ではありません。実際の重複の扱いは画面や記録で確認する必要があります。

1人が複数のアカウントを使う場合もあれば、追加操作が成立していない場合も考えられます。「友人10人」というラベルを付ける前に、表示の単位が人数なのか、登録項目なのかを確認します。人間関係の変化を考えたいなら、同じ人を別の人物として数え直さないことが重要です。

また、昨日5人で今日10人になったとき、人数は2倍でも親密さが2倍になったわけではありません。操作回数を数えるものさしで、信頼や好意の大きさを測ることはできないからです。

## 偏りを見つけた後に確かめる範囲

登録に偏りがあったら、いつ、誰へ紹介したかを振り返れます。同じ集まりで一度に紹介したのか、特定の仕事仲間だけに声をかけたのかで、登録された人の範囲は変わります。アプリを使いたい人だけが参加している可能性も、本人の好みとは別の説明です。

ここで人数を均等にすることを目標にすると、分類の空欄を埋めるために友人を選ぶという逆転が起こります。会話がしやすいか、互いに助けを求められるかは、分類の人数とは別に相手とのやり取りで確認できます。[五行の相性と会話の確認](/blog/compatibility-and-communication)も、分類から関係の良し悪しを固定しないための読み方です。
