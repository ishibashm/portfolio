# ダークモード

ヘッダーのアイコン（広い画面ではサイドバー上部）を押すと、ライト → ダーク → 自動の順に切り替わる。ボタンの読み上げ名とツールチップに現在と次の設定を表示する。初回は自動。設定は端末の `localStorage` の `theme` に保存される。

`src/lib/theme.ts` のスクリプトをルートの `<head>` で同期実行する。描画と React の初期化より先に `html` の `.dark`、`data-theme`、`color-scheme` を設定する。自動では `matchMedia` の変更をその場で反映する。HTML のテーマ属性だけ hydration 警告を抑え、ボタンの初期 HTML はサーバーとクライアントで揃える。

## 配色

従来は Tailwind v4 の明色ユーティリティと `dark:`、`globals.css` の `--wg-*`、ルートレイアウトのインライン変数が混在していた。ページのグラデーション、しるべの CSS、地図・SVG・canvas にも固定色がある。地色と本文色は `globals.css` に移し、`@theme inline` と `.dark` で共有する。記事の表・引用・コード、ネイティブのフォーム部品にも適用する。しるべの素材は既存画像を使用し、ダーク時は CSS で背面に淡い光を敷く。

## コントラスト

sRGB の相対輝度から `(明るい色の輝度 + 0.05) / (暗い色の輝度 + 0.05)` を計算した。WCAG AA の目安は通常の文字が 4.5:1、大きい文字と情報を担うグラフィックが 3:1。半透明の面はカード白を代表値とした。

| -------------------------------- | -------------: | -------------: |

| 見出し／カード                   |        17.85:1 |        14.09:1 |
| 補足文字／カード                 |        10.35:1 |         9.24:1 |

| 良い判定／緑の薄い面             |         6.49:1 |         9.01:1 |

## 確認範囲

- Chrome の PC・モバイルでトップ、`/houi`、引越し4画面、ブログ記事、404、ヘッダー・フッターを確認。画像は `/workspace/dark-mode/after/`。記事の表とコード、しるべの吹き出しも個別に撮影した。
- `/blog` はローカル DB 接続が無いため 500。既存 Markdown を `BlogIndex` に渡す一時プレビューで一覧の見た目を確認した。記事は既存の Markdown フォールバックで表示できた。
- `wealth` の実データ、`arbitrage` の物件・地点のポップアップ、`simulator` の入力後の結果は表示条件が多く、確認は初期状態が中心。管理画面やほかのツールの個別配色も別途確認が必要。
- 次に配色を足すときは文字と背景を対で確認する。地図や canvas に渡す色は、描画面とその上の凡例やラベルも一緒に確認する。CSP でインラインスクリプトを制限する場合は、初期テーマのスクリプトにも適用する。
