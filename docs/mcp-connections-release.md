# AI接続管理画面の公開前配線

PR 15時点では `/profile/connections` は無条件404。環境変数による解除経路はなく、プロフィール画面のリンクもまだ追加しない。管理パネル・表示サービス・Node管理HTTP adapterは未公開。個人用MCPの結合検証が済むまで、この状態を保つ。

現在のページは個人データを読まない静的404で、NextのnotFound境界がnoindexを付ける。next-sitemapは事前生成のnotFoundRoutesを除外する。200を返すnoindexページとして夜間監査へ登録しない。実buildの成果物検査は公開前に残る。公開時にはforce-staticを外し、個人応答のno-store・明示noindex・サイトマップ除外と認証が必要な画面の監査方針を揃える。

## 実装済みの構成

- `createMcpConnectionService`: 本人限定の一覧・単一解除・すべて解除・共有範囲縮小。
- `createMcpConnectionManagementService`: 上記サービスを包み、本人の `presets` だけから同意済みIDの名前を解決する。渡す `clients` はASで事前登録した同じクライアント集合の表示名。ブラウザー入力や外部URLで名前を解決しない。
- `createMcpConnectionsHandler`: `service` に表示サービスを渡す。構造的に同じサービス契約なので、既存Cookie本人確認・CSRF・no-store・固定エラー処理をそのまま使う。マウント先はASと同じcanonical originの `/api/mcp/connections`。Next routeからNode handlerへ無理な変換をしない。
- `McpConnectionsPanel`: 同一originの上記APIにCookie付き・no-storeでアクセスする。GETは最大100接続ずつ。POSTは確認後の解除、全接続解除、同意済み範囲の縮小だけ。全接続解除は表示ページ外も対象。削除済み・壊れたプロフィールの名前を推測せず、IDで識別して解除できる。

画面は出生値・座標・トークンを受け取らない。プロフィール名や接続先名はReactの文字列として表示し、HTMLとして評価しない。日時はUTC表記。最終利用が未記録なら「記録なし」と表示する。PR 17以降の利用記録が未接続でも、架空の最終利用を補わない。

操作後は最初のページから状態を読み直す。共有範囲・確認状態をリセットし、古い選択を使い回さない。失敗時は一覧を消し、部分的に操作が完了している可能性を説明する。通信の自動再試行や、解除の成功を推測した表示は行わない。5秒で通信を中断してもサーバーで処理が完了している場合があるため、再読込で確認する。

## 公開前に残る作業

1. PR 17以降の監査・共有制限、ASのNode22配置、canonical proxy/Host、鍵管理を含め、表示サービスを実際の管理handlerへ注入する。実際の配線はまだ存在しない。
2. 認証済み管理APIから実ストアまで、別本人の分離・範囲縮小・単一/全解除・部分障害を結合検証する。実DB適用と実資格情報の利用は、この実装タスクでは禁止されている。
3. 実サイトログイン、ChatGPT/Claude/Cursorで接続→同意→実行→解除→拒否を検証する。実ブラウザーでもTab/Space/Enter、確認後のフォーカス、狭い画面、スクリーンリーダーの通知を確認する。現在のUIテストはjsdomでのラベル・フォーカス・フォーム送信・操作状態の検査であり、実ブラウザーでのアクセシビリティ確認の代替ではない。
4. no-store、サービスワーカー、アクセスログ/APMの実設定を確認する。個人情報を返すページを共有キャッシュや分析へ送らない。
5. 上記を終えた公開用コミットでページの404を外し、管理パネルと `/profile` のリンクを同時に接続する。PR 21の個人用案内も同時期に揃える。

未完了の間は「利用可能」と案内しない。端末専用設定を再現できないこと、入力値がAIの明示要求で渡り得ること、ログアウトと解除の違い、解除後も送信済み情報を回収できないことはパネルに実装済み。
