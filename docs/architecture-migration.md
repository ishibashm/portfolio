# ポートフォリオサイト アーキテクチャ刷新案

現在のGCP (Compute Engine) + SQLite構成における「容量不足」「管理の手間」「デプロイの複雑さ」を解決するための、モダンなアーキテクチャ案を提示します。

## 経済性比較 (コスト分析)

| 項目 | GCP (現在) | **Vercel (推奨)** | Cloudflare Pages | Railway |
| :--- | :--- | :--- | :--- | :--- |
| **月額費用** | **$0 〜 $15** | **$0** (Hobbyプラン) | **$0** (Freeプラン) | **~$5** |
| **主な内訳** | e2-micro (無料枠外なら$7~), ディスク, 通信費 | 完全無料 (個人利用) | 完全無料 | 基本料金 + 使用量 |
| **DB費用** | VMに含まれる (SQLite) | 無料 (Vercel Postgres Hobby: 256MB) | 無料 (D1: 5GB) | 込み (Volume代) |
| **制限事項** | メモリ不足で落ちやすい (e2-microの場合) | 商用利用不可 (Hobbyの場合) | Next.js機能の一部制限の可能性 | 独自の制限なし |
| **結論** | 無料枠内での運用は難易度が高い | **最も手軽で安価** | コストパフォーマンス最強だが構築難易度高 | 安定しているが有料 |

> **結論**: 個人のポートフォリオサイトであれば、**VercelのHobbyプラン（無料）が経済的にも機能的にも最適**です。GCPの無料枠は「運用管理コスト（時間単価）」を考慮すると割高になるケースが多いです。

---

## 推奨: Vercel + Vercel Postgres (or Neon/Supabase)

Next.jsの開発元であるVercelを利用するのが、パフォーマンス、コスト、運用コストの面で最適解です。

### メリット
1.  **サーバー管理不要 (Serverless)**: OSの更新、ディスク容量の管理、PM2の設定などが一切不要になります。
2.  **高速なデプロイ**: GitHubにプッシュするだけで、ビルドからデプロイまで自動で完了します。
3.  **高いパフォーマンス**: グローバルCDNが標準で付帯し、画像最適化も自動で行われます。
4.  **無料枠の充実**: ポートフォリオ用途であれば、Hobbyプラン（無料）で十分に運用可能です。

### 必要な変更点
現在の構成からの移行には、以下の変更が必要です。

1.  **データベースの変更 (SQLite -> PostgreSQL)**
    *   Vercel（サーバーレス環境）では、ローカルファイルシステムへの書き込みが永続化されないため、SQLiteファイル (`dev.db`) は使用できません。
    *   代わりに、Vercel Postgres（またはNeon, Supabase）などのマネージドデータベースサービスを利用します。
    *   **作業**: `prisma/schema.prisma` の `provider` を `sqlite` から `postgresql` に変更し、接続設定を行うのみで、コードロジックの大幅な変更は不要です。

2.  **デプロイ設定の変更**
    *   `.github/workflows/deploy.yml` は不要になります（VercelがGitHub連携で自動処理するため）。
    *   Vercelのダッシュボードでリポジトリをインポートするだけで完了します。

## 代替案: Railway / Fly.io (PaaS)

もし「どうしてもSQLiteを使い続けたい」場合は、Persistent Volume（永続ストレージ）を持つPaaSを利用します。

### メリット
*   **構成の維持**: SQLiteをそのまま利用可能です（ディスクをマウントして永続化）。
*   **Dockerベース**: コンテナ技術を利用して安定稼働します。

### デメリット
*   **無料枠の制限**: 完全無料での運用が難しい場合があり、少額のコスト（月数ドル〜）がかかる可能性があります。
*   **設定の手間**: Volumeのマウント設定など、Vercelに比べると初期設定が少し複雑です。

## 結論とロードマップ

**Vercelへの移行** を強く推奨します。以下のステップで進めることを提案します。

1.  **準備**: `prisma/schema.prisma` をPostgreSQL用に書き換え、マイグレーションファイルを生成。
2.  **DB作成**: Vercel上でPostgresデータベースを作成（ボタン操作のみ）。
3.  **接続**: 環境変数 (`POSTGRES_PRISMA_URL`, `POSTGRES_URL_NON_POOLING`) を設定。
4.  **デプロイ**: コードをプッシュして移行完了。
