`docs/adsense-rereview-plan.md` が「審査に通るための中身」を扱うのに対し、
この文書は **審査を通った後の広告の置き方**と、審査前でも進められる
**集客・アフィリエイトの打ち手**を扱う。数字は書いた日に実測したものだけ。

`pub-0000000000000000` のような値を ads.txt に出すと、Google に不正な

**コードの変更もデプロイも要らない**（環境変数の更新だけ）。

## 2. 審査を通った後の手順（人がやること）

1. Cloud Run の環境変数に `NEXT_PUBLIC_ADSENSE_ID=pub-XXXXXXXXXXXXXXXX` を入れる
   （`NEXT_PUBLIC_` はビルド時に埋め込まれるので、**ビルドの引数にも**要る）
2. AdSense 管理画面の「プライバシーとメッセージ」で **GDPR のメッセージ**を
   有効にする。Google 認定の CMP なので、自作のバナーは作らない。
   同意の結果は同意モードの既定値を上書きする
3. まず**自動広告をオフ**のまま、下の表の枠だけで 2 週間見る。
   自動広告は CLS の原因（本文の途中に高さ未確保で差し込まれる）に
   なりやすい。使うなら「アンカー広告」と「全画面広告（vignette）」を外す
4. スロットを作って `NEXT_PUBLIC_ADSENSE_SLOT_ARTICLE` /
   `NEXT_PUBLIC_ADSENSE_SLOT_LIST` に入れる

## 3. 頁の種類ごとの配置

**原則。**

- 枠は**本文の区切り**にだけ置く。見出しの直下・ボタンの隣・入力欄の近くに
  置かない（誤クリックを誘う配置は AdSense のポリシー違反）
- 枠の上に「広告」と表記する（`AdBanner` が出す）
- **高さを先に確保する**（`AD_MIN_HEIGHT`。auto 280 / rectangle 250 /
  horizontal 100 / fluid 120）。届いたときに本文が押し下げられない
- **画面の 400px 手前で読み込む**（`AD_LAZY_ROOT_MARGIN`）。最初の画面の
  LCP と回線を取り合わない
- 1 画面（モバイルで 1 スクロール）に 2 つ以上置かない
- 判定の結果（吉凶・段階）と広告を同じ箱に入れない。結果の一部に見える

| 頁の種類                                      | 枠                       | 位置                                                                           | 置かない所                                       |
| --------------------------------------------- | ------------------------ | ------------------------------------------------------------------------------ | ------------------------------------------------ |
| 記事 `/blog/[slug]`                           | article ×1（今）→ 2      | 本文の後・関連記事の前（今）。3000 字超の記事だけ中ほどの h2 の手前に 1 つ足す | 目次の直下、FAQ の中                             |
| ガイド `/guide/*`                             | article ×1               | 手順の後                                                                       | 手順の途中（操作の説明と混ざる）                 |
| 年・星 `/houi/[year]/[star]`                  | article ×1               | 吉方位の表の後                                                                 | 表の中・表の直上                                 |
| 地域 `/houi/area/[code]`・`/houi/pref/[code]` | list ×1                  | 方位ごとの一覧の後                                                             | 方位の一覧の途中                                 |
| 月の日取り `/calendar/[month]`                | list ×1                  | 日取り表の後                                                                   | 日のセルの近く                                   |
| 道具（`/relocation/*`、`/houi/today`）        | list ×1（timing だけ今） | 結果と「読み方と限界」の後                                                     | **入力欄・結果の近く。入力前の画面には出さない** |
| ホーム・ログイン・問い合わせ・プライバシー    | なし                     | —                                                                              | 全部                                             |

**記事の中ほどの枠は、まだ作らない。**`BlogArticleBody` は Markdown を
描くので、h2 の手前に差し込む口を作る必要がある。審査の後、実際の CLS と
RPM を見てから足す（バックログ A-3）。

## 4. 審査前でも使えるアフィリエイト

いまは A8.net 経由で **ハコブ引っ越しサービス（首都圏 4 都県）** と
**楽天市場**がある（`lib/affiliateOffers`）。表示は `AffiliatePlacement` に
まとまっており、`rel="sponsored nofollow noopener"` に直してから描く。

足すなら、**引越しの意思決定の流れに沿うものだけ**。占いの結果を
商品の購入に結び付けない（「吉方位なのでこの業者」は誤解を招く）。

| 候補                               | 置く頁                                                     | 理由                                                                     | 注意                                             |
| ---------------------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------ |
| 引越し一括見積もり（全国）         | `/relocation/timing` の料金の傾向の節、`/calendar/[month]` | 日取りが決まった直後に次にやること。ハコブは首都圏だけなので全国を埋める | 「最安」などの断定をしない                       |
| 賃貸の物件ポータル（提携があれば） | `/houi/area/[code]` の家賃の表の後                         | 街が決まった直後                                                         | 掲載の取り込みは規約で止めている。**リンクだけ** |
| 火災保険・家財保険の比較           | ガイド「引越しの手順」                                     | 契約時に必ず要る                                                         | 健康・金運のような効果を言わない                 |
| 光回線・ネット回線                 | 記事の後                                                   | 転居で必ず要る                                                           | 同上                                             |
| 方位磁針・暦の本（楽天）           | `/houi` の真北と磁北の注記                                 | サイトの説明（磁北のずれ）と直結                                         | 既存の楽天の枠を使う                             |

**載せる前に、各プログラムの規約で「占い・スピリチュアル系サイトへの掲載」と
「成果条件」を読む。**読めないうちは載せない（CLAUDE.md 3 節の規約の決め事と同じ）。

## 5. 集客の打ち手（検索意図の強いテーマ）

既にあるもの（重ねて作らない）: 年・星ごとの吉方位、天中殺、日取りの一覧、
市区町村・県、今日の吉方位、風水（八宅）、記事 79 本。

**新しく頁を増やすより、検索意図が強い問いに既存の頁で答える**ほうが
審査の観点（薄い頁を増やさない）でも安全。LP の案は次のとおり。どれも
**計算と統計で中身が埋まる**ものだけにした。

| 優先 | 案                                   | 検索の問い                             | 中身の出どころ                                     | 新しい頁か                            |
| ---- | ------------------------------------ | -------------------------------------- | -------------------------------------------------- | ------------------------------------- |
| 1    | 「2027年に引越しで避ける方位」まとめ | 2027 引越し 方位 避ける / 五黄殺 2027  | 年盤（暗剣殺・五黄殺・歳破）。星ごとの頁へ振り分け | `/houi/2027` の冒頭を強化（新頁なし） |

## 6. 表示速度（Core Web Vitals）で見つけたもの

- 広告の CLS → 今回直した（高さの確保）
- 広告の読み込み → 今回直した（遅延）
- **自動広告を有効にすると上の 2 つが効かない**（2 節の 3）
- 地図の頁は Leaflet を遅延 import 済み。ホームの天気は静的生成に含めている
  （#1866）。今回は測っていない。**測るなら PageSpeed Insights の実測
  （フィールドデータ）で、ラボの値と混ぜない**

## 7. 残りのバックログ（優先順）

**A. 広告**

1. 審査を通ったら 2 節の手順（環境変数・GDPR メッセージ・スロット）
2. 道具の頁（arbitrage・simulator・market）に timing と同じ list 枠を足す（結果の後）
3. 記事の中ほどの枠（`BlogArticleBody` に差し込み口。3000 字超だけ）
4. 自動広告を使うかの判断（CLS と RPM を 2 週間比べてから）

**B. 集客・SEO**

1. 5 節の 1・2・5（既存頁の強化。新 URL なし）
2. 道具の頁に `WebApplication` の構造化データ（`ToolPageIntro` を使う 4 頁）
3. 記事のうち、題名だけではテーマ外に見えるもの（事業承継・採用・会社の年齢・
   友だちアプリ・苦情件数など 6 本前後）を「引越し・方位」との繋がりで
   書き直すか noindex にするか。**消すかどうかは判断が要る**（記事は DB が正。
   CLAUDE.md 3 節）
4. Search Console で「クロール済み・未登録」の頁を数え、薄い頁の見直しに使う
5. 5 節の 3・4（記事）

**C. コンテンツ**

1. `adsense-rereview-plan.md` の残作業（市区町村の固有文、県の解説）

**D. デザイン**

1. 道具の頁の入力前の画面に、結果の見本（静的な画像）を置く。審査では
   「何をする頁か」が入力前に分かることが効く

   埋め込みを足したら外部送信の表（YouTube の行）は既にある
