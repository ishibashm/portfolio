# Security review — 2026-10-31

Scope: the root Next.js portfolio application, its npm dependency tree, Prisma schema, all tracked SQL, public/private MCP boundaries, API routes and the sole explicit Server Action. Work was performed on `security/hardening-2026-10-31`. This is a source review and local verification, not a production penetration test or proof that no prior compromise occurred. No production DB, credential file, deployment or remote configuration was inspected or modified.

## Validation

- `npm audit`: **0 vulnerabilities**, down from 47. npm is authoritative; existing Yarn and pnpm locks are deliberately not updated. Configure CI/deployment to use `npm ci`, not auto-select another lockfile.
- `npm run build`: passed on Node 22 with dummy non-secret Supabase settings and `DATABASE_URL` pointing to unused loopback port 1. Static telemetry reports the expected unavailable dummy DB and uses existing fallbacks. No real database was accessed. Next's existing middleware-deprecation warning remains.
- `npm test -- --maxWorkers=2`: final result recorded below. No tests are excluded by this invocation. Five existing live/optional integration tests remain skipped by their own conditions.
- The first upgraded test run had 4 failures / 6,223 passes. All four were addressed: preserve minute-precision zoned timestamps in Zod without changing calculation results; add the AI SDK mock's required finish event and strengthen its call-limit assertion; copy new helper dependencies into the isolated Next HTTP fixture. `judge_time_slots` and public/private MCP regression coverage remain enabled.
- `tsc --noEmit`: final result recorded below. The build retains the repository's pre-existing `ignoreBuildErrors`; separate type checking is therefore required.
- Changed-code ESLint: clean in the initial focused check; final check recorded below. Whole-repository lint exposes React compiler/ref rules in untouched components after the config upgrade; these are reported rather than disabled or folded into unrelated UI refactoring.
- New regressions cover bounded streams, rate ceilings, auth-before-I/O, traversal/symlink rejection, private cache headers, owner-bound SQL, malformed contact/search/plan input, verified legacy linking and complete RLS inventory.
- The migration was executed **only in an ephemeral in-memory PGlite instance**, with 56 synthetic tables and seeded permissive policies. Verified RLS, revocation of table and column ACLs, SELECT/column SELECT/INSERT/UPDATE/DELETE/TRUNCATE denial for anon and authenticated, default-deny even with a SELECT grant to an untrusted role, service-role access, idempotence and absent-table handling. This does not validate actual Supabase role memberships or production grants.

## Owner steps before rollout

1. Review and deploy the patched branch only when ready. No push, PR, merge or deployment was performed here.
2. Back up policy/ACL definitions in restricted storage; stage `prisma/sql/20261031_security_rls.sql` against a representative Supabase instance. Review the actual Prisma and dedicated MCP DB roles first: table owners/BYPASSRLS roles can bypass RLS; custom non-owner roles need deliberately scoped policies and privileges. **Do not grant browser roles broad access to restore functionality.** The draft replaces all policies on inventoried tables, including any out-of-repository policies. Confirm intentional custom roles before applying.
3. Apply the new SQL manually, after schema creation. Absent tables are reported and skipped; rerun after creating them. Verify every inventoried table has RLS and expected policies/ACLs; test anonymous access, two different authenticated accounts, authorized API reads/writes, cron and personal MCP. Audit untracked live tables, views, RPC/security-definer functions, storage buckets, role memberships and default privileges separately. `setup_uuid.sql` only creates an extension; it creates no application tables. The nested `katmer-defuddle/knowledge-base` schema has six table names already in this inventory; if deployed against a separate database, assess/apply equivalent protection there separately.
4. Verify privileged keys never appear in `NEXT_PUBLIC_*`, browser assets, logs or history. Follow `incident-response.md` if a leak or compromise is suspected. No blanket key rotation is claimed or performed; encryption keys need re-encryption/reconnection planning rather than blind replacement.
5. Configure distributed firewall/rate/bot controls and provider spending alerts as described in `operations.md`. Confirm whether traffic actually goes through Vercel: repository comments/workflows also reference Cloud Run. Avoid browser challenges on MCP/OAuth and legitimate machine traffic.
6. Approve the personal-data retention/consent proposal before collecting more telemetry or deleting records. Review deletion across browser copies, legacy rows, provider state and backups.

## Limits and items not done

Production RLS state, secret values, environment scopes, prior exploitation and real-user authorization were not inspected. Real DB migrations, key rotation, deletion/retention changes, Vercel settings, push/PR/deployment and live provider calls were outside the authorized scope. No files under `/home/box/.secrets/` were read.

This pass prioritizes concrete exposure paths. It is not a line-by-line audit of every bundled child project, every scraper, external site, RPC or historical commit. Public deterministic/geography APIs remain public by design; legacy validators were not all rewritten into Zod. Generic API limits are per-process and do not constitute a distributed DoS defense; routes excluded for machine-protocol compatibility retain their own controls. CSP script enforcement and a privacy-safe report collector are deferred to compatibility testing. The current build's upstream public weather requests and optional Chromium integration need deployment smoke testing; no scraping or paid API call was deliberately triggered.

The Jev routing skill was consulted, but its configured Python executable was absent; direct deterministic checks and primary-source research were used. No sub-agents were spawned.
