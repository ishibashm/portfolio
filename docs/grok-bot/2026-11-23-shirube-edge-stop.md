# しるべが画面端で体当たりして見える動きの修正（2026-11-23）

- 依頼: #1900 は 12:05 JST にマージ済み（デプロイ中）との本人報告のあと、しるべが右を向いて壁（画面の端）へ歩いていくとき、行き止まりで壁に体当たりしているように見える、とのこと。端の手前で止まり、正面を向くか折り返す。端に向かって歩き続ける状態を作らない。定位置が右端なので、戻るときの歩き方も確かめる。最新の master から新しいブランチ。コードは box 上の Codex CLI（`codex exec -s workspace-write`）。スマホ幅とデスクトップ幅で端の動きを連続撮影。テストと lint を通し、PR を作り CI を待つ。マージはしない。

- 原因:
  - 歩行の目標が `bounds.maxX` まで許されていた。定位置の右余白は PC 4px / スマホ 2px なので、横向きの歩きサイクル（脚を ±24° 振る）のまま右端ぎりぎりまで歩くと、足が壁に当たっているように見える。
  - どちら向きにも歩幅が足りないときのフォールバックが右向きのまま歩き続けうる状態だった。
  - 「定位置に戻る」で床から離れていると跳ぶ経路になり、最初の実装では着地が定位置（右端ぎりぎり）だった。歩行の手前止めだけでは、跳んで戻るときに同じ見え方になり得た。
- 修正内容:
  - 歩行の到達範囲を、端から PC 16px / スマホ 8px 内側に制限する（`walkEdgeInsetPx`）。
  - 端に着いたら歩き続けず、正面を向いて一時停止するか、内側へ向きを変えて折り返す。狭い床で歩幅が取れないときはその場で停止する。
  - 「定位置に戻る」は、床を歩く場合も跳ぶ場合も端の手前で歩行・着地をやめ、そのあと正面のまま定位置まで滑るように収める。脚を振りながら壁ぎりぎりまで歩かない。
  - 関連テストを追加・更新。ローカルで `__tests__/shirubeRoam.test.ts` 45 件、`__tests__/shirubeWanderer.test.tsx` 33 件、合計 78 件成功。変更ファイルの eslint / prettier も通過。
