## 1対1で進めたこと（結果）

本人の承認を得たうえで、次を実施した。

1. 本番（Cloud Run `blog-471319/portfolio-app`、asia-northeast1）が、実行時の接続先を GCP Secret Manager の `database-url` から読んでいた。ビルド用の GitHub シークレット `ENV_FILE` と `DATABASE_URL_OVERRIDE` だけでは実行時の接続先は変わらない、という切り分けをした。
2. 旧接続先のままだったため、DB呼び出しが失敗し、`/blog` が遅く、一部 API が 500 になっていた。
3. Supabase「Blog」の接続設定を更新し（シークレット名だけ記録し、値は残さない）、再デプロイした（GitHub Actions run `42587171403`）。`/blog` と API の応答は回復した。
4. ブログ本文 78 本を、既存行を上書きしない INSERT のみで投入した。別アカウントの残存記事 1 件は、本人の指示で削除した。
5. 足りないテーブルと列は、追加系の SQL だけで整えた。破壊的な SQL と、賃貸の `name_key` / `municipality_key` の一括 UPDATE は実行していない（後者は本人の承認待ち）。
6. 郵便番号データの投入を予約した（11/9 22:45 日本時間）。
