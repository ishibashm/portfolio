# cloud-palette.com デザイン刷新提案書

**コンセプト: 「現代の暦と羅盤（Modern Almanac & Compass）」**  
対象: `cloud-palette.com`（Next.js 16 / React 19 / Tailwind CSS v4 / react-leaflet 5 / 地理院タイル）  
位置づけ: デザイン・フロントエンド設計提案（コード未変更・モック併設）

## 1. 現状診断（本番画面・コード実測ベース）

本番スクリーンショット（PC 1280px / モバイル 390px）および既存実装（`globals.css`、`dark-mode-globals.diff`、`ArbitrageMapInner.tsx`、`MagneticMapInner-sectors.tsx`、`GlobalSidebar.tsx`、`tierDisplay.ts`、`ShirubeBubble.tsx` 等）を精査した結果、現行UIは機能・精度・テスト体制が非常に堅牢である一方、視覚設計に**構造的な4つの課題**がある。

### 1.1 制約1「赤・緑＝判定専用」に対する重大な抵触（現行 `rose-600` の評価）

| 箇所 | 現行実装 | 評価 | 引き起こしている問題 |
|---|---|---|---|
| **主アクセント (`--wg-accent`)** | `rose-600` (`#e11d48`) / `feat/dark-mode` で `#be123c`・`#fda4bf` | **抵触（赤系）** | サイドバーの現在タブ（真っ赤な帯）、リンク下線、ロゴマーク、ボタンが「凶方位（赤 `#dc2626`）」と同じ暖色・赤色相を奪い合っている。特に `/houi/today` では「現在地で調べる」ボタンと「未判定」見出しが同色の赤で並んでいる。 |
| **エリア一覧の丸点** | `/houi/area` の全市区町村チップに赤いドット (`rose-500`) | **抵触（赤系）** | どの街も「凶」や「警告」のマークが付いているように誤認される。 |
| **ハザード「なし」ボタン** | `ArbitrageMapInner.tsx` L1144 `bg-rose-600 text-white` | **抵触（赤系）** | 「⚠️ なし（ハザード非表示）」が選択状態だと真っ赤に点灯し、むしろ危険状態に見える。 |
| **ログイン・稼働表示** | `GlobalSidebar.tsx` L475 `text-emerald-700`、L517 `bg-emerald-50 text-emerald-700` | **抵触（緑系）** | 緑は「吉方位」専用であるべきところ、サイドバー常設の「ログイン」「システム稼働中」に緑を使用している。 |
| **検索半径の円** | `ArbitrageMapInner.tsx` L1563 `color: "#10b981"` | **抵触（緑系）** | 検索範囲の円が `TIER_FILL.A`（`#10b981`・吉2盤）と完全に同一の緑であり、吉方位の境界線と紛らわしい。 |
| **移住先比較マップ凡例** | `wealth-map-pc-map.png`：「所得高い＝赤」「大吉方位＝赤」 | **重大な意味衝突** | 物件・方位マップでは赤＝五大凶殺なのに、移住先比較では赤＝高所得・大吉となっており、サイト内で色の意味が逆転している。 |

> **結論**: 現行の `rose-600`（および `feat/dark-mode` の `#be123c` / `#fda4bf`）は明確に赤系であり、**「緑と赤は判定専用」の原則と真っ向から衝突している**。さらに、すでに `ShirubeBubble.tsx`（L6）では「配色は紺 `#1e2a5a`・金 `#c9a54a`・生成り `#faf7f3`・白のみ。緑や赤は吉凶判定専用のため一切使わない」という正しい設計指針が実装済みである。サイト全体のブランド色を**しるべの羽織色（勝色・紺藍）と羅盤金**へ寄せることで、制約順守・視覚ノイズ削減・キャラクター調和の3つが同時に達成できる。

### 1.2 方位地図の視覚的過密と機能整理の課題

1. **下地（地理院「標準 `std`」）の情報過多**: 赤い国道・緑の高速道路・紫の県道・密集した駅名・線路記号の上に半透明の緑〜赤の扇形を載せているため、道路色と吉凶色が濁って判別しにくい。
2. **8方位ラベルの重なりと視認性劣化**: `arbitrage-map-mobile-map.png`（390px）では、`N / NE / E / SE / S / SW / W / NW` の8枚の札が中心の青い標準ピンの周囲に団子状に重なっている。また `style="text-shadow: 0 0 2px rgba(0,0,0,0.8)"` が白背景に掛かっており、文字輪郭が滲んで古びた印象になっている。
3. **右上コントロール群の肥大化**: `arbitrage-map-pc-map.png` では設定を開くと右上に7〜10段のボタン群が縦に並び、しかも選択色が `stone-700` / `indigo-600` / `rose-600` / `blue-600` / `amber-600` と5色以上に分散して地図の右半分を覆い隠している。
4. **右下エリアの競合**: 地図右下の凡例（`bottom-4 right-4`）と、常駐案内役「しるべ」（`z-[30]` 右下待機）の吹き出しが同位置で競合している（`arbitrage-map-pc-map.png` 右下参照）。
5. **モバイルの縦スクロール吸い込み**: ページ埋め込み地図を1本指でスクロール通過しようとすると地図がパンしてしまい、下部コンテンツに辿り着きにくい。

### 1.3 サイト全体のデザイン・情報設計上の課題

1. **テイストの分裂**: ページ背景にピンク＋アンバーの大型ぼかしオーラ（`blur-[100px]`）と丸みの強い `rounded-3xl` カード（「Warm Glass」）を敷く一方、地図やテーブルには `font-mono text-[10px]` の計器調UIが混在し、e-Stat 公的統計の知的な信頼感としるべの和モダン世界観の間にちぐはぐさがある。
2. **最小フォントサイズの小ささ**: `text-[10px]` が凡例・補助説明・サイドバー見出し等に多用され、モバイルおよび高解像度環境で可読性が低い。
3. **コンテンツ幅の間延び**: `max-w-[1700px]` に引き伸ばされたカードが1280px〜1920px環境で間延びし、視線の横移動が長い。
4. **サイトテーマと地図テーマの分断**: `feat/dark-mode` の `:root.dark` と、地図専用の `useMapTheme`（`localStorage["map_theme"]`）が独立しており、サイトをダークにしても地図がライトのまま残る懸念がある。

## 2. (a) 地図のリデザイン案

新デザインの方向性は **「静かな和紙地図 × 精密な現代の羅盤」**。地図の下地は一歩引き、方位の扇形・境界線・地名・選択フォーカスが主役として浮かび上がる設計にする。

### 2.1 見た目の豊かさ・地図スタイル設計（2段階アプローチ）

#### ステップ1（即効・現行 `react-leaflet 5` 維持）
- **既定下地を `std` → `pale`（地理院淡色地図）へ変更**: 道路や市街地の原色ノイズを一気に約70%削減し、吉凶の扇形色（`TIER_FILL`）が本来の色相・明度差で読めるようにする。
- **CSSフィルタによる「和紙調ミュート処理」**: `pale` タイルに以下を適用し、サイトの生成り地（`#FAF7F2`）と溶け込む上質な地図帳トーンへ整える。
  - ライト時: `filter: saturate(0.38) contrast(0.95) brightness(1.03) sepia(0.08);`
  - 地形の立体感（任意ON / 「土地を調べる」プリセット）: `hillshademap`（陰影起伏図、`maxNativeZoom: 16`）を `opacity: 0.24`・`mix-blend-mode: multiply` で重ね、尾根と谷の陰影を品よく浮かび上がらせる。
  - `photo`（空中写真）・`relief`（色別標高図）にはフィルタを掛けずそのまま表示する（色情報・標高判読を壊さないため）。

#### ステップ2（本格刷新・ベクタタイル化 — `MapLibre GL JS`）
ラスタ地図の限界（「扇形を上に塗ると駅名・地名まで濁る」「ダークモードがCSS反転の擬似表現になる」「回転・高DPI描画が粗い」）を根本解決するため、フェーズ3で **MapLibre GL JS + 無料商用可ベクタタイル** へ段階移行する。
- **レイヤー順序の革命**: ベクタスタイル内で **`[陸・水域・道路] → [8方位扇形・県塗り] → [方位線・距離リング] → [駅名・市区町村名ラベル]`** の順に描画することで、**扇形の上にくっきりした地名・駅名が載る**（プロ品質の地図視認性）。
- **和紙ライト / 深藍ダークの専用 `style.json`**: 陸地・水域・主要道路・鉄道だけを厳選し、コンビニ記号や細街路の視覚ゴミを中縮尺（z8〜z13）で間引く。

### 2.2 8方位の扇形・方位線・中心点・札（ラベル）・選択強調

| 要素 | 刷新デザイン仕様 | 具体的な値・実装指針 |

### 2.3 操作UI・凡例の整理（しるべ共存設計）

現状「右上に最大10段のバラバラな色ボタン＋右下に凡例＋右下に常駐しるべ」という三つ巴の衝突を解消し、地図上の常設UIを**最小3点**へ整理する。

1. **左上（状態ピル）**: 1行コンパクトバー `渋谷区起点 · 2026-11-22 · 三盤合成` ＋ 起点へ戻るアイコン（`44×44px`）。
2. **右上（スリム縦ツールバー）**: `レイヤー設定`（1ボタンでポップオーバー展開）、`全画面`、`現在地`、`ズーム + / -` のみ。すべて統一サーフェス色（アクティブ時のみ勝色）。
   - 「レイヤー設定」を押したときだけ、PCは幅 `288px` の整理された1枚のカード（**プリセット** / **地図の下地** / **重ねる情報** / **参照ハザード** の4セクション）、モバイルはボトムシートで展開。
3. **左下（コンパクト凡例）**:
   - **PC**: 1行横並びスリムバー（高さ `34px`、`S 三盤吉`〜`X 五大凶殺`・`天中殺` の色ドット＋短縮ラベル）。高さ消費を現状の約1/4へ削減。
   - **モバイル**: タップ展開式の `凡例` チップ（`min-h-11`）。
   - **右下は空ける**: 案内役「しるべ」（`z-[30]`）と吹き出しの安全領域を確保し、地図凡例・コントロールとの重なりを構造的に排除する。

### 2.5 ダーク時の地図

- **テーマ連動の一元化**: 現行 `useMapTheme`（`localStorage["map_theme"]`）を拡張し、既定はサイト全体の `:root.dark`（ライト/ダーク/自動）に自動追従。ユーザーが地図内で明示的に切り替えた場合のみ「地図のみオーバーライド（例：夜でも空中写真やライト地図を見たい用途）」を許可する。
- **Leaflet 期のダークスタイル（`pale` ベース改良版）**:
  ```css
  /* 淡色地図をベースに深藍トーンへ反転（海が青紺、道路が銀細工になる調整値） */
  .map-tiles-dark {
    filter: invert(1) hue-rotate(196deg) brightness(0.82) contrast(1.08) saturate(0.42);
  }
  ```
  地図コンテナ背景は `#121622`（深藍黒）とし、タイル読み込み中も白フラッシュを防ぐ。空中写真（`seamlessphoto`）と色別標高図（`relief`）は反転させず `brightness(0.88)` のみ掛ける。
- **MapLibre 期のネイティブダークスタイル**: 陸 `#161925`、水域 `#0D1322`、主要道路 `#2C344D`、鉄道 `#3E4866`、地名ラベル `#D2D8E6`（縁取り `#11141E` `1.5px`）の専用JSONを描画。扇形は暗地で沈まないよう `fillOpacity` をライト比 `+0.06` に設定する。

## 3. (b) サイト全体のリデザイン案

### 3.1 ブランド方向性としるべとの調和

案内役「しるべ」の装束（**紺の羽織 `#1E2A5A`・金の縁取りと羅盤 `#C9A54A`・生成りの和紙吹き出し `#FAF7F2`**）をサイト全体の視覚的核に据える。  
※ しるべの胸元の小さな朱の房飾りはイラスト内の挿し色として残しつつ、UI側には赤系を使わないことで、しるべが画面上で自然に引き立ち、かつ吉凶の赤（凶）と絶対に混同しない秩序を保つ。

- **廃止する過剰装飾**: 背景の大型ピンク／アンバーオーラ（`blur-[100px]`）、カード全面の重い `backdrop-blur-xl`（実機パフォーマンス低下の一因）、`rounded-3xl` の過度な丸み、`rose-600` の真っ赤なタブ帯。
- **新たに採り入れる品格**: 繊細な `1px` 罫線、和紙の温かみある生成り地（ライト）と深藍の夜地（ダーク）、見出しの明朝体（`Shippori Mincho`）、数値の等幅桁揃え（`tabular-nums`）、羅盤の極細金色ライン装飾。

### 3.2 タイポグラフィ（書体・スケール・行間・パフォーマンス配慮）

現行の優れた最適化（`Geist` は `preload: false`、`Shippori Mincho` は `SerifFontLoader` により `requestIdleCallback` 経由で `weight: 400, 700` のみ遅延読込）を**そのまま継承し、追加の和文Webフォント（Noto Sans JP 等、数百KB〜数MB）は読み込まない**。代わりに、OS標準和文の優先順を最適化（Windows で可読性の高い `BIZ UDPGothic` を `Yu Gothic` より優先）することで、**転送量ゼロ増のまま見た目の洗練度を大きく引き上げる**。

#### 書体スタック
- **見出し・ブランド (`--font-serif`)**: `var(--font-shippori-mincho), "Hiragino Mincho ProN", "Yu Mincho", "BIZ UDPMincho", Georgia, serif`
- **本文・UI (`--font-sans`)**: `var(--font-geist-sans), "Hiragino Sans", "Hiragino Kaku Gothic ProN", "BIZ UDPGothic", "Yu Gothic", system-ui, sans-serif`
- **数値・家賃・日付・座標 (`--font-mono`)**: `var(--font-geist-mono), ui-monospace, SFMono-Regular, Menlo, monospace` ＋ 数値要素には必ず `font-variant-numeric: tabular-nums` を適用。

### 4.2 既存 `dark:` クラス（341箇所）および `useMapTheme` との整合方針
- Tailwind v4 の `@theme inline` マッピングをそのまま維持するため、すでに `bg-theme-surface` / `text-ink` / `border-theme-border` を参照する箇所は**変数値を差し替えるだけで一斉に刷新**される。
- `GlobalSidebar.tsx` や `page.tsx` 等にハードコードされた `bg-rose-600` / `text-rose-600` / `border-rose-100` / `text-emerald-700` は、`bg-accent` / `text-accent` / `border-theme-border` へ置換する。
- `useMapTheme` は `document.documentElement.classList.contains("dark")` を既定ソースとしつつ、`MutationObserver` で `:root.dark` の切替を即時購読する設計へ統合する。

## 6. リスクと対策

| カテゴリ | リスク内容 | 影響度 | 具体的な対策 |
|---|---|---|---|
| **テスト・判定整合** | 色トークン変更時に `tierPalette.test.ts` や `tierPaletteSeparation.test.ts` が失敗する、あるいは画面間で吉凶の色・語彙がズレる。 | 高 | `TIER_FILL` 6色と `BLOCKED_FILL` は Phase 0〜3 では一切変更せず、UIの4役だけを入れ替える。変更が必要な場合は必ず `paletteChecks.ts` の ΔE 検査（通常≥15、色覚≥8）を自動通過させる。 |
| **ダークモード競合** | `feat/dark-mode` ブランチとのコンフリクト、および既存341箇所の `dark:` クラスとの見え方不整合。 | 高 | 新トークン名は `feat/dark-mode` の変数名をそのまま踏襲する。Phase 0 は必ず `feat/dark-mode` マージ直後に着手し、旧 `dark:text-rose-*` 等を grep で全件棚卸しして置換する。 |
| **地図タイル規約・可用性** | 地理院タイルの出典・加工明記漏れ、または無料外部タイル（OpenFreeMap等）の障害・仕様変更。 | 中 | 地図の常時表示領域に出典リンク（加工時は「加工して作成」）を固定配置。外部無償サービスへ単一依存せず、Phase 1〜2は公的インフラの地理院タイル、Phase 4は地理院ベクトルまたは自前 R2 上の PMTiles を主軸にする。 |
| **パフォーマンス劣化** | 和文Webフォント追加や MapLibre 導入（gzip 約200KB）による初期描画・LCP悪化。 | 中 | 和文Webフォントは増やさない（既存の `SerifFontLoader` 遅延ロード維持）。地図は現状どおり `dynamic(..., { ssr: false })` で非地図ページへバンドルを漏らさない。重い `backdrop-blur-xl` をカードから撤去し、実機スクロールfpsをむしろ改善する。 |
| **モバイル操作の学習コスト** | 1本指スクロールガードを入れた際、「地図が動かない」と戸惑う利用者がいる可能性。 | 低〜中 | 地図に触れた瞬間に1.5秒だけ「2本指で地図を移動 / 全画面で操作」のトーストを表示し、地図右上に目立つ「全画面」ボタンを常設する。 |
| **表現の適切性（法的・倫理）** | 刷新に伴うコピー書き換えで、吉凶の断定表現や過度な煽り表現が紛れ込むリスク。 | 中 | すべての吉凶表示に「参考情報」「九星気学上の目安」「客観データ（家賃相場・ハザード）と分けて検討」という注記方針をコンポーネント設計に組み込む。 |
